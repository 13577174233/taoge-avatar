# 客服知识库运维（电商事业中心专用）

客服知识库不是「问答摘抄」，是**可被客服当场念出来、且不会被投诉和判罚**的话术资产。三条铁律先立住：

1. **每条话术都要有源**：卖点、价格、保质期、赔付标准，任何一个数字必须能追溯到表、公告、商品页或旧库已核条目；取不到就留空写「以标签为准」，不补估。
2. **话术边界要单独成栏**：每个品类都必须有「我方不要碰」清单（禁说表述），否则客服会把竞品的强卖点顺手借过来，变成虚假宣传。
3. **改完必须断言再发版**：知识库是单文件 HTML 的多子页结构，改数据最容易踩的是「子页常显」和「卡片不展开」两类回归，发版前必须过 §5 清单。

## 一、数据源台账（先确认源，再动手）

| 用途 | 源 | 位置 |
|---|---|---|
| 产品 SKU、规格、零售/活动/最低价、主推渠道 | 2026 年渠道产品销售价格策略.xlsx（Sheet1，第 4 行起） | `0-N-GSY/.../06-专项产品与营销/电商产品价格体系/` |
| 保质期、旧口径、已下市款 | 现有 `KBPROD` 旧数组（从 HTML 取，见 §5） | 运营中台 HTML |
| 售后责任编码 A–H 类 85 条 | 售后（登记表、编码、月报）.xlsx | `0-N-GSY/.../15-客服资料库/客服资料/` |
| 7 渠道赔付标准 | 各平台官方规则公告（2026 口径） | 已核表见 HTML `KBPAY` / `KBPAYCOMP` |
| 竞品卖点基线 | 竞品鲜花饼淘系基准 md + 本轮五品类采集 | 设计团队指挥台目录 |
| 客服内部资料 | 15-客服资料库（手册、话术、台账） | `0-N-GSY/.../15-客服资料库/` |

**价格表读法**：第 1 行大标题、第 2–3 行双层表头、第 4 行起数据；列序为 分类 / 编码 / 图片 / 名称 / 规格 / 零售 / 活动 / 最低 / 直播间 / 拼多多 / 小红书 / 京东自营 / 天猫 / 主推渠道 / 各店铺销量。表内**没有保质期列**，保质期只能从旧 `KBPROD` 反查。

## 二、产品话术卡：10 字段结构（结构不可改）

```
[商品编码, 名称, 规格, 保质期, 品类, 一句话摘要, [4–6 条核心卖点], 完整话术, 适合场景, 注意点]
   p[0]     p[1]   p[2]   p[3]    p[4]     p[5]          p[6]            p[7]      p[8]      p[9]
```

渲染函数 `renderProd / renderProdChips / setProdCat / renderProdList / toggleProd / copyProd` 全部按 10 元组取值，**加字段或改顺序会直接废掉渲染**；要扩字段只能先把渲染函数一起改。

- **卖点 4–6 条**：一条一个可验证的事实（克重/枚数/肥瘦比/保质期/工艺/口感），不写「品质优良」这类空话；同一品类不要 6 条都在讲同一件事。
- **完整话术 80–120 字**：客服能一口气念完，含 1 个规格数字 + 1 个活动价区间 + 1 个场景落点。
- **注意点**：写「不能说什么」和「必须先问什么」（过敏原、怕咸/怕甜、短保提醒），不写内部流程。
- **适合场景**：只写电商渠道场景（自食/办公室/送礼/团购/直播福利），不写门店、到店核销。
- **价格写法**：零售价与活动价只放「注意点」里做内部口径，且统一句式「零售 X 元、常见活动价 Y 元，对客只说区间，以页面实价为准」。详情页口径是不标价，话术里也不报死价。

**品类键（`PRODCAT`）**：固定六档 `全部 / 云腿 / 鲜花 / 现烤 / 礼箱 / 月饼`，与价格表的六个分类对齐（云腿酥系列→云腿、鲜花饼系列→鲜花、现烤系列→现烤、伴手礼+电商专款→礼箱）。新增档位必须同步改 `PRODCAT` 数组，否则 chip 计数与筛选全错。

## 三、竞品对照：三栏法（每个品类都建）

表头固定四列：**竞品 / 对方在打的卖点 / 我方可以怎么接 / 我方不要碰**。

- 「对方在打的卖点」只写商品页或官网能看到的原话与数字，标注口径年份；取不到写「未取得」。
- 「我方可以怎么接」必须落在我方**有证据**的差异点（规格、克重、保质天数、规格覆盖、双线组合、年份链条），绝不接对手的含量、层数、销量这类我方无检测值的项。
- 「我方不要碰」是本轮最值钱的一栏：把对手强卖点里我方不能借的部分逐条列出，客服照念即违规的表述直接禁掉。
- 每个品类末尾加一句「一句话结论」，回答「这个品类的仗该怎么打」，不要只堆表格。

五品类基线（鲜花饼 / 云腿月饼·云腿小饼 / 现烤 / 滇式伴手礼 / 月饼）与三家口径见 `references/rival-comparison-matrix.md`。

## 四、周更流程（每周一次，只改变化项）

1. **取 diff**：价格表 SKU 与 `KBPROD` 编码比对（有则新增、无则下市待确认）→ 竞品页重抓（对比上轮「对方在打的卖点」有无变化）→ 平台规则查变动（只看官方公告）→ 售后编码表查新增类目。
2. **分级处置**：新增 SKU 建卡；下市 SKU 不删卡，改品类为「已下市」或移出 chips；价格变只改 `p[9]`；卖点变才改 `p[6]/p[7]`。
3. **只改差异**：整段重写风险最高（历史上重写 CSS 区块把 `.kb-pane{display:none}` 覆盖掉，导致四个子页竖排成一页）。能用定点替换就用定点替换。
4. **校验**：跑 §5 清单，全部断言通过才发版。
5. **发版**：`cd 产物目录 && lark-cli apps +deploy --file-path ./冠生园电商设计团队总工作台.html --app-id app_17hwrwc34yq`，看返回 `ok` 字段不看 exit code；`+release-get` 轮询 `status=finished` 才算上线；上线后**禁止**再访问链接自检。
**版本与日期显示规则**：品牌区固定一行 `总工作台 vX.Y · YYYY-MM-DD`。X 为大结构变更（页面重组、菜单重构、子页拆分）；Y 为**功能迭代序号**，每完成一次功能级迭代（新增或重建一个功能模块、扩品类、批量回补 SKU）就 +1，修 bug 或只改文案不升 Y。日期永远取本轮实际改动日，不沿用上次。侧边栏底部固定为「昆明冠生园电商事业中心 / 仅供内部使用」，不放经营目标这类会上公网的数字。
6. **留痕**：改前复制到 `_backup/总工作台-<改动主题>-<日期>.html`；同时更新页内「数据更新日期」。

## 五、发版校验清单（回归防线）

**静态**：抽取 `<script>` 到 `/tmp/kbchk.js` 跑 `node --check`；断言 `PRODCAT`、`KBPROD` 数组能 `json.loads`；断言 `id="page-*"` 恰好 7 个、`.kb-pane` 恰好 5 个。

**运行时**（必须断言计算值，不能只数 class）：
- 五个子项逐个点击，每次**可见的 `.kb-pane` 必须只有 1 个**（`getComputedStyle(p).display !== 'none'` 计数）。
- 产品页 `#prod-box` 子元素数 = KBPROD 条数；`#prod-chips` 子元素数 = 6，且文字为「全部 N / 云腿 x / 鲜花 x / 现烤 x / 礼箱 x / 月饼 x」。
- 点一个品类 chip，卡片数等于该品类条数；点第一张卡，卡 `class` 含 `open`、正文 `display=block`、`gridColumn` 为 `1 / -1`。
- 竞品面板 `h4` 分区数 = 品类数，每张表 `tbody tr` 行数 = 3（或该品类实际竞品数）。
- 八个一级菜单逐个点，每次**可见 `.page` 只有 1 个**，且首页到巡检周报 7 个页面 id 一个不缺。

**环境坑**：窗口不在前台时 `window.innerWidth/Height=0`、`getBoundingClientRect` 全 0、media query 误判单列、`bu.screenshot()` 报 viewport unavailable。此时 `getComputedStyle` 的 display 仍可用。要几何断言就用 `/tmp/wrap.html`（固定 1200px width 的 iframe）+ `python3 -m http.server 8899 --directory /tmp` + `contentDocument` 同源读取，校验完 `pkill -f "http.server 8899"`。

**作用域坑**：页面里的 `switchSvc / toggleProd / setProdCat` 在 `bu.js` 里不可见，必须 `element.click()` 触发；`f.defaultView.scrollTo` 可用，但顶层被外链带走后 `contentDocument` 会变 null，重新 `navigate` 即可。

## 六、与其他 skill 的边界

- 回复策略、投诉分级、语气模板 → `doubao-customer-service`（方法层）。
- 竞品新品与货架扫描 → `taoge-ecom-product-intelligence` / `taoge-ecom-competitor-watch`（采集层）；本 skill 只负责「采集结果 → 客服可说的话 + 不能说的话」这一层转化。
- 定价、折扣授权、毛利底线 → `taoge-ecom-price-governance`。
- 门户结构与菜单规范 → `taoge-guanshengyuan-workbench`。

## 适用边界（2026-11-20 补）

- 适用：客服话术资产生产、竞品同品类对照、平台赔付标准、售后责任编码、禁说清单、知识库周更发版。
- 不适用：通用客服对话答复（走 `doubao-customer-service`）、赔付裁决本身、平台规则最终裁定。

## 失败模式与兜底

- 如果价格表更新但话术未刷 → 以价格表为准，话术标版本号并列入本周刷新。
- 如果平台规则变动 → 只写「已变更，待核」，不猜新规内容。
- 如果竞品对照缺数据 → 留空并标「待补」，不编卖点。
