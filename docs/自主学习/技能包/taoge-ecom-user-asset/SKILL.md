# 用户资产与复购经营（电商事业中心专用）

## 一个判断：退款率不是履约问题

2026 中秋退款率 28.59%（红线 ≤15%）。把它当成快递问题，就会一直赔钱；按五类拆开，才知道该改口味、改包装、改详情页还是改物流。

## 客户分层与 LTV

四层：首购／复购（≥2 单）／高频（≥4 单或年消费 ≥2 次节令）／沉睡（>180 天无单）。

LTV＝客单价 × 年频次 × 留存年限；复购层看 LTV，首购层只看首单转复购率。2027 核心爆品复购率 ≥20%；私域复购的获客成本约是投放拉新的三分之一量级。

## 私域四池：一池一指标，不混算 GMV

| 池 | 任务 | 唯一指标 | 内容形态 |
|---|---|---|---|
| 企微好友池 | 蓄水 | 加粉率 / 触达率 | 到货提醒、售后关怀 |
| 社群池 | 激活 | 周活跃人数 | 福利日、试吃反馈 |
| 会员池 | 复购 | 30/60 天复购率 | 积分、生日礼、节令预售 |
| 短信唤醒池 | 召回 | 唤醒率 / 回访成本 | 沉睡唤回、临期清仓 |

四池 GMV 分开记账：私域成交不等于自营店成交，混算会高估私域价值。

## 退款归因五类（先分类，再谈压降）

1. **口味不符**（太甜/太咸/异味）→ 改配方或改试吃装，话术降预期。
2. **破损漏液**→ 包材与内衬，转 SR 供应链前端域。
3. **预期落差**（图文与实物差、大小/枚数不符）→ 详情页与主图实拍。
4. **物流超时**→ 仓配 SLA 与节前截单。
5. **误购凑单**（拍错规格/凑单退）→ 规格命名与满减门槛设计。

用脚本按原因字段自动归类并算占比：

```bash
python3 scripts/refund_attribution.py 退款明细.csv --top 5
```

CSV 至少包含「原因」与「金额」两列（列名含 原因/reason、金额/amount 即可识别）。

## 详情页预期管理清单（上架前逐项打勾）

- 克重、枚数、层数、保质期四项写在主图后第 2 屏。
- 礼盒内配与拆层**实拍**，不用渲染图；赠品单独标注规格。
- 到手价与"券后价"分开展示，避免结算落差。
- 口味描述用可验证的词（减糖百分比、配料表），不用"超好吃"。

## 客诉 SOP

首响 ≤30 秒；退款工单 24 小时内定性归类（五类之一）；差评 48 小时内回访并记录；周报进经营复盘，同步给产品与内容。

## 复购与召回节奏

T+7 复购券（同品类）→ T+30 交叉推荐（节令/日常盘）→ T+60 沉睡唤醒（限量款或试吃装）。三段各设退出条件，不做无差别群发。

## 口径

退款率＝退款订单数／成交订单数（注明是否含部分退款）；金额占比按财务入账价；复购率按自然年内≥2 单计。

## 适用边界（2026-11-20 补）

- 适用：客户分层与 LTV、私域四池运营、退款与差评五类归因、详情页预期管理、客诉 SOP、复购与召回。
- 不适用：内容投放与达人执行（走 `taoge-ecom-content-ops`）、定价与控价（走 `taoge-ecom-price-governance`）、客服话术资产生产（走 `taoge-ecom-cs-kb-ops`）。

## 失败模式与兜底

- 如果缺客户分层数据 → 用订单频次与客单价两维粗分，并标注「粗分，待数据校验」。
- 如果差评原因混杂 → 按口味/破损/预期落差/物流超时/误购五类占比排序，不逐条解释。
- 如果私域无触点 → 先给最小可行池（企微＋短信），跑通再加社群与会员。
