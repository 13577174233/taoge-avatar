# 职业经验复盘蒸馏总控

## 使命与边界

把"过去做过的项目"从存档文件变成可调用的能力资产：看得懂产物、提炼得出方法、封得住规则、用得上现业。总控负责路由复盘流水线、九簇能力索引与质量门纪律；具体能力卡详情见 `references/capabilities/`。

**做**：项目产物深读建档 → 能力条目提取 → 跨项目归簇 → 三重验证 → 能力卡/skill 封装 → 现业迁移对照与回灌。
**不做**：不重做过往项目原始交付物；不凭记忆蒸馏（每条能力须可定位源文件路径）；不改/删既有技能文件，只新增；未过三重验证不封可执行 skill；海外 SaaS 语境方法不直接套国内快消语境。

## 何时触发

- 一批历史项目/报告/产物需要复盘，提炼"当时是怎么做的、用到什么能力"；
- 要把零散经验归纳成可复用方法、规则或自有 skill；
- 要建能力档案卡、跨项目能力矩阵、现业迁移对照或缺口清单；
- 新会话续跑某条复盘流水线，需按状态台账恢复上下文。

## 六阶段流水线

按顺序推进，每阶段更新迭代台账（断点续跑，不从头重来）：

1. **立档**：建目录结构、团队/角色/技能/伙伴配置、档案卡与能力卡模板、状态台账。
2. **外部补缺**：检索外部候选 skill，LICENSE 先行，评估方法密度/宿主依赖/语境界面；适配才装，不适配只取可迁移单条方法本地化重写并标来源许可。
3. **逐项目深读**：逐目录完整阅读产物，出能力档案卡（项目概况/角色分工/方法动作/能力条目/踩坑反模式/工具产物/迁移候选/核验记录）。
4. **能力归纳**：条目跨项目归簇（硬技能/方法论/工具链/软技能四层），出能力矩阵、现业迁移对照、缺口清单。
5. **蒸馏封装**：过 V1/V2/V3 三重验证与晋级门五条判据，写七段能力卡；封包前在活跃技能中查重；成熟簇按需晋级独立子 skill，未晋级保留为总控内能力卡。
6. **回灌迭代**：把能力挂到现业角色与场景，写可证伪验证信号，T+30 复盘命中情况，台账版本迭代。

## 质量门纪律

- **三重验证**：V1 来源充分性（可定位源文件支撑）／V2 可执行性（换合法新输入能做完并核出结果）／V3 任务增益（减少遗漏、统一口径、稳定交付）；不通过分流为 reference / needs-review / rejected。
- **晋级门五条**：独立意图／独立契约／独立运行／独立复用／独立评测；前 3 必过，后 2 至少过 1。未晋级能力保留为总控内能力卡，不单独建目录。
- **查重**：封包前在活跃技能库检索近邻；已有承载则并入或只补接线，不重复建包；目录名不重名，frontmatter `name` 与目录一致。
- **加法纪律**：用户手改定稿为权威基准，只做加法不覆盖；多版本 V1/V2 不覆盖旧版；新素材入库后增量蒸馏、版本号追加。
- **证据边界**：素材不全时降级结构并显式标注缺口，不冒充全量依据；引用数据核对源文件，合计=分项之和，多口径并存须注明。
- **接线要求**：每条蒸馏能力至少连 2 条既有技能线；每条写边界与反模式误用清单（≥3 条）。
