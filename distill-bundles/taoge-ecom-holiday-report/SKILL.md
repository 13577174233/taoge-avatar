# 电商节庆总结报告（电商事业中心专用）

> 版本 v2.1（2026-11-03 项目方法论蒸馏 E1-E6 补全）

面向昆明冠生园食品有限公司·电商事业中心的节庆/年度经营总结报告生成与迭代。核心价值：复用已沉淀的报告结构、数据口径与质检纪律，减少每轮从零构思。

## 判断模型接入（来自 taoge-jiahua-ecom-playbook）

复盘先判后写：八章是骨架，判断在骨架之上。

| 模型 | 在本技能的落点 | 不合格表现 |
|---|---|---|
| M6 节庆倒排 | 复盘首页给"计划 vs 实际节点表"，标晚几天、损失多少 | 只写"活动圆满结束" |
| M9 复盘四件套 | 问题页统一四列：现象/量化影响/责任/动作（谁·几号·标准） | "有待提升""加强管理" |
| M4 渠道贡献毛利 | 节庆 GMV 拆到渠道贡献毛利，达播给单场损益 | 只放 GMV 占比饼图 |

售后与平台处罚必须单列，不能只写成绩；同类企业档案里"罚款与退款同步放大"就是反例。模型全文见 `../taoge-jiahua-ecom-playbook/references/ecom-thinking-models.md`。

## 报告标准结构（八章）

1. **报告核心总结**：3 条高度概括（总盘达成/结构亮点与风险/次年目标与总纲）
2. **销售工作总结**：目标达成总览（表：渠道类型×2024/2025/目标/实际/达成率/同比）+ 渠道结构与贡献（表：平台×实际/去年/同比/占自营）+ 销售节奏与履约
3. **产品销售深度分析**：总量与礼盒/散装结构 + 爆款单品表（数量口径）+ 承压大单品表 + 分渠道产品表现 + 产品深度洞察（卡位验证/差距/赛道坐标/结构风险）+ 价格与客单结构
4. **渠道与达人复盘**：兴趣电商/搜索电商/新品联名投放表（ROI/退款率/结算率）/达播复盘/履约复盘
5. **工作亮点与问题解决方案**：亮点 7 条左右（数据驱动）；问题按深层归因展开（经销商/平台/供应链/内容/达人/MCN 等）+ 2027 动作映射
6. **产品质量问题总结与改进**：A 类客诉/售后差评/包装破损/履约品质联动 + 改进动作
7. **市场洞见与行业趋势**：行业大盘/线上占比/消费结构变化/区域品牌/次年预判（核心关键，不展开）
8. **次年销售规划**：目标与定位总纲（保底/挑战+总纲一句话）+ 渠道策略 + 产品策略（突破口/结构矩阵/风险规避）+ 营销与达人策略 + 供应链与组织

## 数据口径校验清单（每轮必查）

- 总盘 = 自营 + 经销商；缺口 = 目标 - 实际，缺口分解占比合计应 ≈100%
- 表内达成率 = 实际/目标；同比 = (实际-去年)/去年；用工具复算，不凭印象
- 平台占比为分平台口径（未含团购等补充渠道时合计可≠100%，需在交付说明提示，不擅改）
- 同一指标多口径并存时（如全渠道第一单品 vs 单店口径、MCN 净 ROI vs 商城投放 ROI）保留并存并注明口径
- 引用行业数据须附机构来源（勤策消费研究、中国焙烤协会、行业白皮书、艾媒咨询等），标注"行业预估/非官方"口径

## 排版规范（质检必检项）

- 全文宋体（eastAsia=宋体，run 级 rFonts 校验）
- 标题层级：章标题（一、六、七）用 Heading 1；节标题（1.x/二三四五/竞品对标/问题与解决方案/7.x）用 Heading 2；"五、"等章标题不得误用 Normal 正文样式
- 正文段落首行缩进 24pt（2 字符）；表注顶格无缩进
- 数字与中文混排统一空格（"节前两周""晚 5-10 天""9 月 5 日"）；"2-3 款""50+ 款"
- 句末标点闭合（不得残留分号结尾）；列表编号连续（(1)-(8) 不得跳号）

## 报告编号与交付规范

- **编号格式**：`GSY-DS-YYYY-XX-NNN`，例如 GSY-DS-2026-09-001
  - YYYY=报告年份；XX=报告类型码（01春节/02端午/03中秋/04年度总结/05述职/06专项/07经营分析）；NNN=三位流水号
- **密级分级**：内部（电商事业中心内部流转）/ 机密（含毛利/经销商协议，限管理层）/ 公开（可对外的市场洞见段）
- **口径标注**：每个数据表标题行必须标注口径（自营/全渠道/含团购/不含团购等），多口径并存时并列注明
- **署名链**：封面页须标注「编写人→复核人→审批人」三级
- **封面版式**：报告标题（一号宋体加粗居中）+ 编号（右上角）+ 密级（右上角红色）+ 日期 + 版本号（如 V1.0）
- **文件命名**：`GSY-DS-YYYY-XX-NNN_报告名_YYYYMMDD_vX.Y.docx`

## 编辑与迭代纪律

- 用户手改的定稿是权威基准，只做"加法"升级，不覆盖其任何既有内容
- 多版本并存：新版本用唯一命名（对标定稿质检版V10.1 等），不覆盖旧版
- python-docx 替换文本注意 run 边界：短串可能跨 run，用"合并全文→写回首 run→清空其余"的段落级替换
- 新增段落样式用 deepcopy 源文档同类段落 pPr/rPr，避免样式不匹配
- 每轮改后必须 audit（--source 指向改前未动文件）+ 渲染逐页验证

### E2. 红队质询五问（每版交付前必过门禁）

战略报告顾问逐版审阅，五问 checklist：

1. **判断主线是否可验证可推翻**——核心判断是数据支撑还是主观臆断？（对应 H01 三实模型：事实→现实→共识，先列事实再做归因再下结论）
2. **建议是否可落地**——每条建议是否带 6-12 个月可预见结果 + 验证信号 + 证伪条件？（对应老板"建议须给未来可预见结果"要求）
3. **风险与取舍是否说透**——优先项/放弃项/重审条件是否明确？不是只写亮点不写风险
4. **合规扫描**——广告法绝对化用语、包装≤3层/≤3公斤新规、标糖政策是否逐项过？
5. **老板看完能拍板哪几个决策**——若报告只堆数据不出决策，打回重写

> H01 三实模型引用：每份复盘/规划先列事实（数据）→现实（归因）→共识（结论+行动）三段落，不跳步。

### E3. 5页综述体迭代链（V1→V8 精炼纪律）

老板要"5页综述"时，从全量报告精炼到 3800 字左右：

**精炼路径**：完整版 33,149 字 → 5页综述 1,660 字 → V2 1,802 → V3 1,755 → V4 2,001 → V5 2,779 → V6 2,783 → V7 3,119 → **V8 终版 3,830 字**

**迭代纪律**：
- 用户点赞段落必须保留（如"三句话看懂"段落），不删
- 已确认版本上增量编辑，不全量重写（V(N+1) 在 V(N) 基础上改）
- 每版出新文件名 V(N+1)，旧版不动
- 逐版标注"用户确认"日期

**关键转折**：
- **V5**：加"三句话开篇 + 建议带预期结果"
- **V6**：标题改内置 Heading（verifier outline=模块数）
- **V8**：加"判断主线 + 验证信号 + 可拍板决策清单 + 三情景（Base/Upside/Downside）+ 可预见结果与证伪"

### E4. 八步执行 SOP（动笔前→交付）

```
Step 1 动笔前    Read 老板提纲 docx + word/docx-editing.md；写 outline.md（模块标题原样 + 每段要点 + 数字来源）
Step 2 写作中    正文中文引号；标题用 doc.add_heading（内置样式）；产品五维 checklist（结构/口味/价格带/包装/设计）
Step 3 生成后     audit.py → 0 错误；verifier docx outline → headings=模块数；docx page-count（LibreOffice 实测页数）
Step 4 战略审阅  战略报告顾问红队质询：判断主线可验证性、建议可落地性、风险与取舍、合规扫描 → 审阅意见并入迭代说明
Step 5 视觉自检   转 PDF → artifact-preview render → Read thumb.jpg
Step 6 增量迭代   已确认版本上增量编辑，不全量重写；用户点赞段落必须保留
Step 7 版本管理   每次出新文件名 V(N+1)，旧版不动
Step 8 交付      present_files + ≤300字迭代说明（含战略审阅差异）
```

**已知硬伤修正**：页数须 LibreOffice 实测（不能凭估）；ASCII 引号统一中文引号；标题必须用 doc.add_heading 内置样式（V5 outline=0 的教训）。

### E5. 报告二分法（先判类型再走结构）

动笔前先判断本次报告属于哪一型，再走对应结构与语气：

| 维度 | 客观分析型 | 创新汇报型 |
|------|-----------|-----------|
| 用于 | 中秋/年度总结、经营分析 | 年度规划、战略建议、述职 |
| 方法论 | H01 三实模型（事实→现实→共识） | R17 穿越时空判断 + R09 非常主张非常证据 |
| 语气 | 数据说话、不臆测、数据差就说差（R24 纪实报道） | 有主张、有取舍、有可预见结果 |
| 证据密度 | 高密度数据，每条结论带数据链 | 主张配成比例证据（如"低糖+320%"配销量×复购×客单×毛利四条数据链） |
| 结构 | 先列事实→归因→结论行动 | 先抛核心结论（R06 叠叙）→展开论证→决策问题（R14 苏格拉底提问） |

> 两种报告不能混用结构和语气。客观分析型不做前瞻判断，创新汇报型不堆数据。

## 去 AI 味与严谨用词

- 保真第一：只改"怎么说"不改"说什么"，数字/事实/来源不动
- 常见修正：明显≠明细、受≠受到、取消≠砍；删除"模板""赋能""抓手"等空词（业务确认过的可保留）
- 用户手改过的句子（如竞品段落）优先尊重原意，仅做错别字与标点修正

## 市场情报证据库（2026-10-21 蒸馏迭代）

- 证据库位置：12-市场情报/（主文档《市场部报告库-电商蒸馏-2024-2026》32 条可引用数据均带机构+页码；技能卡见《技能迭代建议-电商情报技能包》）
- 第7章"市场洞见与行业趋势"引用统一格式：「数据—报告名—页码」；内部口径以销售数据为准，外部数据标注机构与"行业预估"
- 核心节令证据：礼盒单件 100-300 元占 76.29%（艾媒 p15）；购买时间节前 1 周 45.75%/前 2 周 38.77%（p16）；综合电商 62.2%/即时零售 41.98%/新型电商 36.82%（p23）；食品礼盒净利率 15%→6-8%、食饮占企业福利预算 30-50%（凯度 p22/p26）；地域美食靠直播讲食材（月饼直播销量占比 58%，抖音 p26）
