# 创意流水线驱动认知包（Creativity Pipeline Driver）

> **一句话定位**：创意不可控不是因为没灵感，是因为没标准；把「大创意」拆成标准动作、标准模板、标准验收，创意就能像产品一样匀速生产。
> **来源**：华楠·怎样打造创意生产流水线（HN001–HN011 共 11 篇 S 级归档，2026-11-07 全量收官；页面「11/11」与目录 11 项完全一致）。

---

## 一、总图（一句话记住）

**创意流水线 = 定标准（HN002–HN005）× 固化模板（HN006）× 转成培训（HN007）× 限时演练（HN008）× 标准化验收（HN009）× 持续迭代（HN010）**，底座是「购买机制这一人类行为不变」（HN011）。

两个前提必须同时成立：**时间可控**（HN001/HN008 把研发用时压住）与**质量稳定**（HN004/HN005 把标准写死）。只压时间不写标准，等于逼人交次品；只写标准不限时，等于永远交不出来。

## 三、建线 SOP（6 步）

1. **先定不确定性的边界**（HN001/HN002）：统计过去 10 个项目「从立项到定稿用了多久、卡在哪一步、延期多少天」，把最不可控的那一步单独拎出来作为第一改造对象。目标先定「延期率」，不先定「出几个爆款」。
2. **拆动作**（HN004）：找一位老手，把这件事从头到尾拆成 20–40 个动作，逐条写「做什么、做到什么算完成、依据什么判断」。判断句必须能落到事实（消费者原话、货架观察、历史数据），写不出依据的动作就是还没显形。
3. **写标准**（HN005）：每个动作给一条可判定的描述（是/否、达标/不达标），定性标准要附事实依据；明确一条纪律——**老板的意见也要服从方法与规律**，否则标准第二天就失效。
4. **做模板**（HN006）：把重复动作固化成模板（版式固定区位、话术固定结构、评审固定表单）。模板只允许在「迭代」环节改，执行环节不许临时发挥。
5. **转培训**（HN007）：编一册可查的研发手册，配三件套——考试（关键岗满分才晋升）、顺口溜（把 16 字与关键判断编成口诀）、内训师（中层晋升须持内训师资格）。
6. **限时演练＋双关验收＋迭代**（HN008/HN009/HN010）：设一小时车间做组装演练，产品大会做第二道验收（两道关都有模板）；每季度收提案，由流程委员会判断是否进流程；出问题先回流程描述找纰漏，不先怪执行者。

## 四、应用场景映射

| 场景 | 适用律 | 落地 |
|---|---|---|
| 电商内容团队（短视频/图文） | HN004 HN006 HN008 | 把一条带货短视频拆成「选题—母体—购买理由—符号—脚本—拍摄—剪辑—封面」动作表；每步写完成标准，再压进一小时车间做日更演练 |
| 中秋/端午礼盒文案与视觉 | HN003 HN005 | 先用 16 字咒定母体（送礼场景的时令与体面）与购买理由，再写标准：包装正面 3 秒内必须看到什么、卖点句不得超过多少字 |
| 品牌叙事与符号体系 | HN003 HN006 | 母体词根、超级符号、货架呈现固定成模板，新品类直接套用，不每次从零想创意 |
| 新品开发与上市节奏 | HN001 HN002 HN009 | 目标先定「研发延期率≤5%」，产品大会当第二道验收，评审表单固定 |
| 团队培养与岗位晋升 | HN007 | 研发手册＋考试＋内训师三件套；把「能不能按手册做出达标品」作为晋升硬条件 |
| 内容质量下滑复盘 | HN010 HN011 | 先查流程描述是否有纰漏（母体、购买理由、符号哪一环写虚了），再查执行；回到货架前看购买机制是否变了 |
| 判断流水线是否压制人 | HN011 | 看员工是否只会照单执行、无法解释为什么这么做；解法是让人理解规律（母体与购买机制），不是取消流程 |

## 五、边界

- **样本单一**：方法来自读客一家公司的出版与图书营销实践，品类是「文化产品＋货架零售」；纯艺术创作、To B 解决方案、非标服务需重新判断哪些动作可标准化。
- **标准化不等于低质化**：标准创意解决的是「及格线以上的稳定输出」，突破性创意仍需保留一条不受流程约束的探索通道，否则组织会失去上限。
- **前置投入大**：拆动作、写标准、编手册、做考试通常要 3–6 个月且占用老手时间，短期看是负担；没有一把手持续推动会半途而废（HN008 明确要求「极大意志力」）。
- **不适用于容错为零的环节**：涉及食品安全、法规标签、医疗表述的内容，标准必须由合规与法务前置确认，不能只靠创意标准。
- **不承诺销量**：流水线提高的是「按时按质交付的概率」，不保证每件作品都卖爆；把流程当销量保证是误用。
- **免 AI 化输出**：简体中文、零 emoji、结论先行、表格化，不写「赋能／抓手」类空话。

## 运行检查点与失败处置（2026-11-13，统一纪律）

四个 STOP 与三条失败分支见调度层 `taoge-cognitive-os/references/06-run-checkpoints.md`：数据缺失写「数据缺口」不补零｜口径冲突两口径并列不二选一｜真实下单与对外发布只给方案、执行由本人确认｜超边界明说并指向对应包。

失败分支：数据接口失败 → 用最近一次可用数据并标注日期，不虚构当期数值｜模型算不出 → 输出「模型不可用 + 缺哪些输入」｜被要求超能力 → 退回边界声明并指向对应包。
