# 智能体工程驱动包（Agent Engineering Driver）

> **一句话定位**：Agent 能不能干活，取决于四件事——任务边界写得清、动作结构停得住也解析得了、工具补得上模型短板、评估线画得出；框架只是把这四件事的脚手架，不是答案。
> **来源**：Hugging Face 官方《AI Agents Course》中文版（`huggingface/agents-course` 的 `units/zh-CN`，78 节 / 240,979 字符，2026-11-08 官方 Markdown 源直取，AGE001–AGE036 共 36 律）。
> **归档位置**：`04_课程学习/Hugging Face Agents 课程（中文版）/`（`_catalog_HFAC.md` 目录表、`｜全文合订本.md` 唯一正文载体、`_laws_HFAC_b1.md` 唯一蒸馏载体）。

## 一、总图

**模型 × 工具 × 循环 → 动作结构 → 框架选型 → 检索与多体 → 生产与评估**，五层递进，每层只解决一个失败模式。

| 层 | 解决的失败模式 | 核心律 | 一句话判据 |
|---|---|---|---|
| ① 概念层 | 把 Agent 当聊天 | AGE001–AGE009 | 没有工具与循环，就只是问答；循环不闭环就会在同一处反复失败 |
| ② 动作层 | 想得对但做不成 | AGE010–AGE015 | 停不住、解析不了、参数不清，工具等于装饰 |
| ③ 框架层 | 为架构而上架构 | AGE016–AGE022 | 流程能用 if/for 写清的，不需要框架；图的代价是调试面变厚 |
| ④ 检索与多体 | 数据接不进、任务切不开 | AGE023–AGE028 | 切不清就别拆多体，拆了只是把一次调用变成五次 |
| ⑤ 生产层 | 跑通了不敢上线 | AGE029–AGE036 | 没有评估线，就不知道它在退化；能跑通 ≠ 能上线 |

## 三、搭建 SOP（7 步）

1. **先判要不要 Agent**（AGE001／AGE021）：这件事是否需要「外部动作 + 多步决策」？只要一次问答能给结论，就用普通流程或单次调用，不上 Agent。
2. **写清任务边界**（AGE009）：把目标写成一句可判定真假的话；多于一个目标就先拆任务，别让一个提示背三个结果。
3. **定动作结构**（AGE010／AGE011）：要复用中间结果、要处理图像与复杂对象，用代码动作；要被外部系统消费、要严格校验参数，用 JSON 动作。
4. **设计工具**（AGE002／AGE012／AGE013／AGE014）：每件工具回答「补了模型什么短板」；参数名称与类型写死写全；按任务域分包，不一次全塞；有副作用的工具先读后写。
5. **选框架**（AGE016–AGE022）：先用手写小库跑通循环；确需状态图、分叉与人工介入才上 LangGraph；以检索为中心上组件式框架；单 agent 快速跑通用轻框架。
6. **接检索或拆多体**（AGE023–AGE028）：先定位数据在哪一层再定检索方式；确需多体时指定唯一编排者，交接用结构化字段。
7. **画评估线再上线**（AGE029–AGE036）：trace／span／延迟成本三件套先接上；离线回归 + 在线抽样双轨；模型、提示、工具定义任一变动都重跑；过线标准写清通过率、成本上限与回滚方式。

## 四、场景映射

| 场景 | 适用律 | 落地做法 |
|---|---|---|
| 电商内容生产 agent（多平台改写 + 素材生成） | AGE013 AGE014 AGE026 AGE030 | 工具按「文案生成／图生成／发布」分包；发布类工具走「先预览后提交」；用编排者串流程，不让各工具互相调用；批量任务并行跑以压延迟 |
| 投研日报 / 行情复盘 agent | AGE003 AGE005 AGE015 AGE031 AGE034 | 行情与公告必须走工具取实时数据，不靠模型记忆；取数失败要回传原因供重试；每日产出与原口径对比，改一版跑一次回归 |
| 技能库治理 / 多 skill 编排 | AGE016 AGE021 AGE027 AGE028 | 先把循环手写跑通再谈框架；能用脚本判定的规则不要交给模型；多 skill 之间只传结构化结果，不传叙述 |
| 家庭教育与个人 IP 内容线 | AGE002 AGE009 AGE030 | 模型擅长结构与改写，实时政策与录取数据必须走检索；一次只产一个可验收结果，避免一次生成全套 |

## 五、边界

- **本课是官方教程，不是研究综述**：代码动作优于 JSON 动作的论断引自论文《Executable Code Actions Elicit Better LLM Agents》，属特定实验条件下的结论，不等于所有场景都该用代码动作（AGE010／AGE011 已按场景二分）。
- **框架推荐带作者立场**：原文称 LangGraph 是「最适合生产环境的框架」，属作者判断，选型仍须按自身流程复杂度与观测能力评估（AGE022）。
- **数字随版本漂移**：课程中的模型名、价格、配额会过期；本包只保留结构性判断，不搬运会过期的数值。
- **不替代安全与合规审查**：有副作用的工具（下单、发消息、写库）必须另设权限与审计，Agent 框架本身不提供合规保证（AGE014）。
- **不适用于纯算法推导与模型训练**：本包给工程判断，不给反向传播、RLHF 目标函数的推导细节。
- **免 AI 化输出**：简体中文、零 emoji、结论先行、表格优先；不写「赋能／抓手」类空话，不把课程原文改写成营销话术。

## 运行检查点与失败处置（2026-11-13，统一纪律）

四个 STOP 与三条失败分支见调度层 `taoge-cognitive-os/references/06-run-checkpoints.md`：数据缺失写「数据缺口」不补零｜口径冲突两口径并列不二选一｜真实下单与对外发布只给方案、执行由本人确认｜超边界明说并指向对应包。

失败分支：数据接口失败 → 用最近一次可用数据并标注日期，不虚构当期数值｜模型算不出 → 输出「模型不可用 + 缺哪些输入」｜被要求超能力 → 退回边界声明并指向对应包。
