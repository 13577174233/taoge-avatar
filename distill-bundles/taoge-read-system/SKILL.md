# 个人读书系统（图书蒸馏 v2.11）

单本图书的完整蒸馏流水线：书籍档案核验 → 整书阅读提炼 → 跨平台声量分析 → 专业书评 → 四合一 HTML（读书笔记+平台书评+朋友圈+小红书）→ 更新检索总表（HTML）→ 封面与小红书配图归档，全链路成品化交付。

## 目录结构（每本书一个目录）

```
个人读书系统/
├── 00-体系说明与索引.md
├── 01-读书检索总表.html
├── 01-<书名>/        ← 第1本（序号按读毕顺序）：<书名>-读书笔记.html（四合一）+ <书名>.jpg（封面）+ <书名>-xhs-封面/金句卡/观点卡.jpg
├── 02-<书名>/
├── …
└── 模板/              ← 读书笔记四合一模板.html、检索总表字段规范.md
```


## 工作流（每本书按序执行）

### 1. 书籍档案核验 + 整书阅读与核心提炼

- 用户给书名时，先经 `general_search` / `web_fetch` 获取该书公开资料：官方简介、目录、核心观点、章节精华、经典金句、作者与成书背景。搜索关键词用「书名+书评」「书名+核心观点」「书名+目录」「书名+豆瓣」多组并行；多卷/同名书先按作者+出版社消歧。
- 书籍档案字段必须查证并注明来源：书名 / 作者 / 译者 / 出版社 / 出版年 / 页数 / ISBN / 豆瓣评分（含评价人数）。
- 用户提供书籍文件（PDF/DOCX/EPUB/MD）时，优先读取文件本身（PDF 走 pdf 技能，DOCX 走 word 技能），再以公开资料交叉补证。
- **版权红线**：不输出书籍全文、不批量复制原文；只提炼观点、结构、金句（金句限短引并标注出处），长段落一律转述。
- 产出「深度解读」（v2.6 升级，替代原"核心内容提炼+全书总结"两节）：
  1. **一句话主旨**（30 字内）
  2. **论证链条**：作者怎么从前提推到结论，用 3-5 步因果链写清，不是罗列观点
  3. **章节地图**（保留 tree，多卷分卷）
  4. **核心观点提炼**（按章，每章 2-3 点，每条带"它解决了什么问题"）
  5. **反常识点**（3-5 条：哪些结论与读者直觉相反，为什么作者是对的）
  6. **经典金句**（3-5 条短引）
  7. **适用边界**：什么人/什么情境下这本书的结论不成立
  8. **跨书呼应**：与已读书目中哪本互文/互补/对立（查蒸馏瓶书目索引表）
  9. **我的三点启示**（从原"与我的连接"压缩成 3 条可行动项，不写感想）
  10. **一句话可复述**

### 2. 跨平台书评与声量分析

按平台分渠道采集，每平台至少 2 条独立来源再下结论：

- 豆瓣：`general_search` 用 `site:douban.com 书名` 检索评分、短评、长评；优先精读 2–3 篇高赞长评；多卷分别查评分。
- 小红书：`general_search` 用 `site:xiaohongshu.com 书名` 检索笔记标题与摘要；无独立内容时如实标注"书单常客/声量积累期"，不编造。
- 视频号：`general_search` 用 `书名 视频号 解读` 检索；结果不足时用 `video_search`。
- 抖音：`video_search` 搜书名，采集解读视频标题、账号类型、互动信号与解读主线。
- 平台声量差异（如卷二评分明显低于卷一）必须如实呈现，并写进专业书评判断。

产出「读者印证」（v2.6 精简，替代原"平台声量分析"大段表格）：豆瓣/小红书/视频号/抖音各 1-2 句核心判断（热度、口碑倾向、代表性争议），不堆互动数据；然后用一张"观点聚类表"（推崇/冷静/争议 三列，每列 2-3 条短引）收束；最后 1 句"与我阅读提炼的印证或分歧"。读者画像不再单列，并入印证句。

### 3. 专业书评总结

以「资深阅读者·饕哥」人设输出（财经/销售类洞察打底，拒绝 AI 腔，敢点名取舍）。结构：一句话总评 → 这本书解决了什么问题 → 最有价值的 2–4 个观点及其成立边界（每条标注局限）→ 最薄弱处 → 适合谁读/怎么读 → 终判徽章（饕哥评分 + 精读/泛读/避雷，多卷分别标注）。

### 4. 生成四合一 HTML（核心交付物）

按 html 技能规范，把四块内容合并到一个自包含 HTML 文件 `<序号>-<书名>/<书名>-读书笔记.html`：

- **读书笔记（深度解读）**：书籍档案、一句话主旨、论证链条、章节地图、核心观点提炼、反常识点、金句摘录、适用边界、跨书呼应、我的三点启示、一句话可复述、**蒸馏知识包（内嵌，第6步产出）**
- **读者印证与专业书评**：四平台各 1-2 句核心判断、观点聚类表（推崇/冷静/争议）、与我阅读的印证、专业书评（饕哥人设终判）、信息来源表（压缩为 5 列简表）
- **朋友圈读书笔记**：可直接复制的文案 + 配图建议
- **小红书读书笔记**：账号适配（实测「读书的饕哥」主页）、爆款方法论表、标题备选（3选1）、图文正文（可复制）、完整笔记包（标题+正文+标签一键复制）、配图成品展示、封面设计规格、发布建议

执行要求：

- 动手前先 Read `html/SKILL.md` 及其 `references/design/frontend-design.md`；模板骨架见 `assets/reading-note-template.html`（四合一，含完整包与配图区），在其占位处填真实内容。
- 单文件自包含：CSS/JS 内联，不拆外部文件；页内锚点导航切换五大板块；响应式适配电脑/手机。
- **朋友圈文案固定风格**（用户真实发文风格；**v2.7 重写版**，替代已用滥的旧三段式）：
  - **200–300 字**（v2.9 校正：低于 200 字内容太薄，用户明确要求扩充；超过 300 字微信折叠过多）。
  - **禁用固定句式**："这本书不会告诉你 X，但它会告诉你 Y"（前两本连用，已模板化）；禁用"学会……拒绝……"三连排比；禁用破折号金句收尾。
  - 结构四段：①**我的处境**（写"我"的真实场景，**不许拿书里的例子充当**）；②**全书核心观点**（挑 2–3 个能立住的，把全书骨架说出来——只给单点反差会显得内容太少）；③**一句判断**（大白话，像跟同事说话，不排比不升华）；④**一个动作**（今晚/下次就能做的那种）。
  - 不堆书名、作者、评分，不用 emoji，不写"智商税/赋能/底层逻辑"这类词；收尾固定标签 `#读书涛哥的分享`。
  - 写作用 `doubao-human-signal` 规则去 AI 味；定稿过"文案三关"（见下）。
- **小红书板块（v2.11 定稿写法：六零件干货版）**：正文 **650–750 字**（"六零件"版实测 696 字，信息密度与读完率平衡最好）。
  - **第一原则是给东西，不是写得像**：把书里最值得总结的写出来——**可数（读者能数清有几块）、可命名（每块 4–6 字起个名）、能带走（截图就能用）**。抒情、铺垫、书评腔一律不进正文。
  - **开场不自我介绍**：一句读者视角的冲突场景（如"打游戏能通宵，上班两小时就累——真不是自制力的问题😮‍💨"）；禁止"哈喽我是XX／我 50 岁还在跟自己较劲"这类自报身份开场。
  - **立论一句给骨架**：紧接开场说清这篇能拿到什么（如"全书 18 章，把'上瘾'拆成 6 个零件👇"）。
  - **六个模块（按书真实骨架切，不凑数）**：每块 `① 4–6 字动宾标题` 顶格 → 2–3 行解释，用书中具体例子或数字（俄罗斯方块十格宽／马里奥前十秒零文字／失败成本决定留存），不写抽象概括。
  - **排版规则（一目了然优先）**：模块之间空一行；`①②③` 顶格、不缩进；**不用单行 `-` 分隔、不用 📌/🍃 双符号、不用数字键帽 `1️⃣`**（页面字体下渲成蓝底方块）。全文 emoji 控制在 3–5 个，只用于开场情绪与收尾提示。
  - **收尾归因于结构**：把现实困境（反馈太慢／失败太贵／规则太糊）归到结构而不是意志力，给一句 `💡` 结论（如"别改意志力，改结构"），最后 1 个能一句话回答的具体问句。
  - **每条模块自检**：换个书名还能原样搬过来吗？能 → 是通用套话，重写；必须长在这本书的机制上。
  - **不写书评短板**（"这本书方案给得不够"属书评板块）；**不抄样本的敏感词替代写法**（touzi/zui/tui荐 属平台规避手法，不作写作方法）。
  - **完整笔记包**：标题行 + 正文 + 标签一次复制，**正文不重复存第二份**。
  - 标签 10 个，含 2 个长尾词（书名 + 领域词），其余混热门。
  - 配图 3 张（封面/金句卡/观点卡，3:4 竖版 1080×1440，pure-image 生成，**统一视觉系统**：主色取书封、标题用同一种衬线字体、装饰用同一套几何元素）；**配图观点必须与正文六零件一致，不得沿用旧版要点**。
- **小红书配图命名**：`<书名>-xhs-封面.jpg`、`<书名>-xhs-金句卡.jpg`、`<书名>-xhs-观点卡.jpg`（带书名前缀，防多书同名覆盖），与本书 HTML 同目录、相对路径引用。
- 封面图：优先 `image_search` 检索真实封面并下载到 `<序号>-<书名>/<书名>.jpg`；检索不到或无版权图时按 doubao-creative-design 生成。本地电脑 HTML 内一律用相对路径引用。
- 交付前按 html 技能跑 `scripts/shot.py` 自检，检查重叠/溢出/报错/破图（sticky 导航滚动拼接的瞬时重叠属噪音，用顶部截图核实）；AI 图文字问题只记录并披露，不自动重生。
- **全书思维导图板块**：读书笔记内置静态 HTML 思维导图（`.mm-root` 中心卡 + 金色脊柱 + `.mm-grid` 分支，响应式 4/2/1 列）；并同步输出 `<书名>-思维导图.png`（Chrome headless 截取思维导图区域，deviceScaleFactor=2 后裁空白），与 HTML 同目录、HTML 内以 `<img>` 引用，供单独转发。
- 文件命名语义化：`<书名>-读书笔记.html`（冒号改全角：，同名书加作者后缀）。

**文案三关（v2.7 新增，朋友圈与小红书正文定稿前逐条过）：**

1. **换人关**：这段话换一个读书博主也照样能发吗？能 → 重写，直到只有这一个人、这一本书才说得出来。
2. **场景关**：第一句是概念还是画面？是概念（"游戏不是逃避现实的出口"）→ 改成一个能看见的场面（"凌晨两点，我盯着第 37 关的 '再来一次'"）。
3. **删句关**：删掉最后一句，整段是否还成立？成立 → 最后一句是废话，删。
4. **页面用 `refactoring-ui` 做诊断**：层级（主次是否一眼可分）、组间距（组间 > 组内）、行长（正文 45–75 字符，中文约 26–38 字/行）、文字色不超过三档。诊断发现问题只改被点名范围。

**HTML 硬性结构规范（v2.1 固化，缺一不可，生成后逐项核对）：**

1. **全局 `.wrap` 容器（内容居中的唯一机制）**：`</header>` 之后必须紧跟 `<div class="wrap">`，包住全部 5 个 `<section>`，并在 `<footer>` 之前闭合 `</div>`。`.wrap{max-width:920px;margin:0 auto;padding:0 22px}` 保证内容居中、左右留白。**漏掉此容器 = 内容全宽贴边（已踩坑：2026-10-12 纳瓦尔宝典）**。
2. **Hero 标准结构**：`.eyebrow`（PERSONAL READING NOTE · 个人读书笔记）→ `<h1>《书名》</h1>` → `.sub` → `.hero-row`（`.cover` 容器内放 `<img>` + `.meta` 容器内放档案 `<table>`）。禁止改用 `cover-wrap`/img 直接挂 `.cover`/`.data` 表格等非模板类名（已踩坑：顶部 Hero 塌陷缺失）。
3. **生成后结构比对**：打开模板与最近一本已验收笔记（如 `03-后劲/`），比对 section 容器、Hero 类名、kicker 序列、图片相对路径；差异必须先确认再交付。
4. **验收渲染检查**：交付前渲染截图核验——宽屏下内容左边界应有明显留白（约 ≥20% 视口宽），表格、正文、思维导图均不得贴满全宽；移动端 Hero 封面与档案表正常堆叠。
5. 模板与 CSS 为唯一结构源：新书 HTML 从 `assets/reading-note-template.html` 复制 CSS 与骨架，只替换正文内容，不重写结构、不新增未定义类名。

### 5. 更新检索总表 + 交付

1. **更新检索总表** `个人读书系统/01-读书检索总表.html`：每本书一行，字段见 `references/index-spec.md`；封面缩略图与笔记链接用相对路径；同步更新 header 统计（本数）。
2. **维护索引**：`个人读书系统/00-体系说明与索引.md` 版本号与版本表追加一行（记录本次变更要点）。
3. **交付**：四合一 HTML、检索总表 HTML、体系说明经 `present_files` 交付；小红书配图 3 张与封面图经 `<RichMediaCard>` 交付（本地绝对路径）；告知打开方式与"复制完整笔记包"用法。

### 6. 二次蒸馏：内嵌 HTML + 合并进饕哥读书蒸馏瓶

每本书的蒸馏做两件事，**不为单本书建独立 skill**：

1. **内嵌到本书 HTML**：在「读书笔记」板块末尾（一句话可复述之后、`</section>` 前）加一个「蒸馏知识包 · 已并入饕哥读书蒸馏瓶」区块，用 `.distill` 卡片样式（浅金底、金色左边框，CSS 加在 `.kicker` 定义之后），内含：一句话主旨 / 可复用框架 / 金句 / 应用场景 / 边界与误用。md 版书籍在"一句话可复述"后补同名小节。
2. **合并进单一 skill**：把本书蒸馏成一节，追加到同一个合并知识库 `.user_skills/taoge-distill-bottle/SKILL.md`（单文件合集），并更新该文件内书目索引表；节结构=主旨/可复用框架/**决策规则（可执行的 if-then 判断）**/**反模式误用清单（3 条常见错用）**/金句/应用场景/边界/原著档案。
   2b. **进库前过质量门**（v2.11.1，外部方法论 cangjie RIA-TV++，详见蒸馏瓶「拆书质量门」节）：每条框架先过三重验证（来源充分/可执行/任务增益），再用 RIA++ 六段落成字段（R+I→框架、A2→应用场景、E→决策规则、B→边界与反模式），最后问三道压力题（诱饵题、跨书混淆、代表任务）。只跑逻辑不跑 compile，本系统仍不建一书一 skill。
3. **内容取舍**：只抽可迁移骨架；平台声量、朋友圈、小红书正文属个人发布层，不进 skill；不复制原文，金句限短引。**决策规则**必须写成可判断的句子（如"当你面临控制权与价格冲突时，选控制权"），不是形容词；**反模式**必须写清"别人常怎么误用这本书的结论"。
4. **校验与登记**：`quick_validate.py` 校验合并 skill 通过；`02-图书蒸馏技能索引.md` 书目映射追加一行；检索总表对应行小字统一挂 `taoge-distill-bottle`（不挂单本书名）。
5. 新书默认执行本步，除非用户明确只要四合一笔记。

## 输出与交付

- 每本书交付：四合一 HTML（读书笔记+平台书评+朋友圈+小红书，小红书可一键复制，内嵌「蒸馏知识包」）、检索总表 HTML（更新）、体系说明（版本更新）、封面图 + 小红书配图 3 张（与 HTML 同目录）；本书蒸馏节追加进合并知识库 `taoge-distill-bottle`（第 6 步），登记进 `02-图书蒸馏技能索引.md`。
