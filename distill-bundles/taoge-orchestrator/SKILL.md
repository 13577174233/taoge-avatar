# 饕哥分身 · 统筹总控

> **一句话**：分身负责"怎么想、怎么说"，本技能负责"怎么排、怎么收"。
> 统筹不是把活干得更多，是让每一步都有出处、有产物、有验收，断了能接上。

---

## 一、什么时候用

| 用 | 不用 |
|---|---|
| 一次交付多份产物（报告＋表＋图＋稿） | 单个事实问答 |
| 步骤之间有依赖，前一步错了后面全废 | 单文件局部改写 |
| 预计 5 次以上工具调用、跨半小时以上 | 一次搜索／一次查数 |
| 中途可能被打断、换会话、跨环境（本机↔云主机） | 纯闲聊与讨论 |
| 需要多个业务技能或专家团协同（电商/投资/教育/健康/内容） | 已有既定模板、照做即可 |
| 用户说"统筹一下""排个计划""分几步""接着上次做" | — |

**触发后第一句话**：先讲清"这件事我按几步做、每步产出什么、什么算完成"，再动手。

## 二、五段流程（每段都有硬产物，不许空转）

### 1 定题：需求澄清
- 只问会改变范围/结论/交付形态的问题，一次问完，最多 3 个。
- 用户已给的信息不重复问；能从附件、项目库、历史产物查到的，先查再问。
- 输出：**一句话目标 + 边界（做什么/不做什么）+ 验收口径**。
- 工具位：`task-clarifier`（需要深挖时显式调用）、`interaction_ask`。

### 2 拆林：任务树
- 任务拆到"一个人一次能做完、能独立验收"的颗粒度；标出依赖与关键路径。
- 每个节点必须写清：产出物、判定标准、所需输入（哪个文件/哪份数据/哪个账号）。
- 超过 7 个节点就先砍：本轮只做关键路径，其余进"待办池"。
- 工具位：`task-forest`（要跨会话追踪或导出 HTML 时）、`task_create`（会话内）。

### 3 立档：磁盘计划文件
- **存放口径（2026-11-07 用户定稿）**：一律进 `项目库/<域>/`，不散在主目录、不放桌面、不放 /tmp。
  - `<域>` 取 01–07 七个主题目录之一（01_投资_金融 / 02_图书_蒸馏 / 03_内容_创作 / 04_教育_学习 / 05_教育_升学 / 06_技能治理与体系 / 07_个人_生活，以项目库实际目录为准）；跨域任务放主域，副域只留指针文件。
  - 目录命名：`<域>/<任务名>_作战包/`，同一任务多轮迭代续用同一目录，不新建 v2/v3 目录。
- 固定三件套：
  - `task_plan.md` —— 步骤、依赖、当前状态（唯一权威状态源）
  - `findings.md` —— 已查实的事实、数据出处、踩过的坑（带路径/URL/页码）
  - `progress.md` —— 时间线：做了什么、结果、下一步
- 规则：**状态只写在这一份里**，聊天里说"已完成"不算完成，以文件为准；作战包自身排进项目库索引，交付时把最终产物移出作战包、按各域交付规范归位。
- 工具位：`planning-with-files`。

### 4 推进：分工与断点
- 每个节点开工前，先确认"这一节点用哪个技能/哪个专家角色、输入齐不齐"；不齐就补，不许边猜边做。
- 一次只推进一个节点；同层可并行的（检索/生图/取数）并行，收口统一。
- 卡住先换通道再报障（换命令/换来源/换实现），同一动作失败两次必须换路径，不许重复重试。
- 断点：被打断前把"做到哪、下一步第一步是什么、哪些文件已落盘"写进 `progress.md`。
- 工具位：`pause-and-resume`（用户要求暂停续做）、`session-handoff`（换会话/换机器）。

### 5 收口：质量门与交付
交付前逐项过（对应 `output-quality-gate`）：

| 门 | 查什么 |
|---|---|
| G1 输入 | 用户给的附件/数据/口径是否读全，有没有用摘要代替原文 |
| G2 范围 | 有没有越界改动、有没有漏掉用户点名的那一项 |
| G3 事实 | 每个数字有出处（文件—页码/URL/计算过程），推断与事实分开标 |
| G4 产物 | 生成后**用不同于生成路径的方式**回读核验（打开文件/渲染/抽样重算） |
| G5 形态 | 交付物就是用户要的那一种（Word/表/图/PDF/链接），不是半成品 |
| G6 说明 | 交付说明写清：产物名、路径、打开方式、验证方式、仍存缺口 |

**交付即闭环**：产物进项目库对应目录，索引/台账同步更新，临时文件与中间版本清理（删前先按 md5 判重）。

## 三·五、技能选择与触发判定（v1.1 新增）

> 库内已有 270+ 技能。选错技能的代价不是"做得差"，是**读错一份几千字的 SKILL.md、走错一套流程、把上下文烧光**。
> 依据：SWE-Skills-Bench（arXiv 2603.15401）配对评测 49 个技能 / 565 个任务，**39 个零提升、平均增益 +1.2%、3 个因子版本错配反而 −10%**；writing-skills 实测"description 写了流程，模型就照着描述做、不读正文"。

### 七条选技规则

| # | 规则 | 判断句 |
|---|---|---|
| R1 | 先判"要不要技能" | 一次问答、一次查数、单文件小改 → 不读任何 SKILL.md，直接做 |
| R2 | 一个任务只挂 1 个主责 | 主责技能 ≤1，支撑技能 ≤2；超过 3 个说明任务该拆 |
| R3 | 先看边界再读正文 | description 里的"不用于/不替代"命中你的场景 → 立刻换下一个 |
| R4 | 装新技能前先问"替代谁" | 说不清替代关系、只增加能力的，不装（token 是硬成本） |
| R5 | 技能是企业级上下文时看版本 | 技能假设的字段/流程与当前项目不符 → 只借方法，不套步骤（版本错配会负增益） |
| R6 | 触发含糊就问一句 | 两个技能都像 → 用一句话问用户选哪个方向，不猜 |
| R7 | 报错即换路径 | 技能脚本失败两次 → 换实现，不换交付标准 |

### 触发体检法（改 description 前后各跑一次）

- 一条 description 只该回答"**什么时候用**"，不写"内部怎么做"（写了流程，模型会照着流程走而不读正文）。
- 四件齐备才算合格：**触发场景** + **不适用边界** + **产物形态** + **长度 ≤1000 字符**。
- 2026-11-08 已给 15 个高频技能补"不用于"边界句；新增技能沿用同一模板。



1. **状态单一**：`task_plan.md` 是唯一进度源；口头"已完成"不作数。
2. **证据先行**：没有出处的事实不写进产物；占位符宁可留着，不许编。
3. **一次一里程碑**：不并行推进互相依赖的节点，避免互相污染。
4. **越界即停**：用户只让改 A，就不动 B；发现 B 有问题只提示，不顺手改。
5. **失败两次换路径**：换命令/目录/来源/实现，不换交付标准。
6. **交付前必须换路复核**：文件存在≠正确，非空≠完整。
7. **不擅自扩张**：不为"显得做得全"增加用户没要的章节、图表、版本。
8. **断点必留痕**：离开前 3 行字：做到哪、下一步、已落盘文件清单。

## 五、与其他能力的分工

- **taoge-avatar**：决定"以谁的视角、用什么模型、什么语气"——统筹不越权替它定调。
- **user-profile-keeper**：维护长期画像；只有用户明确要求或确认时才写。
- **humanize-pro**：成稿的语气校准与去 AI 指纹；统筹负责在质量门里给它留一道。
- **task-clarifier / task-forest / planning-with-files / pause-and-resume / session-handoff**：本技能的执行组件，按需逐个调用，不重复实现。
- **output-quality-gate**：G1–G6 的细则与检查表。

## 六、最小可用模板（复制即用）

```markdown

## 目标
一句话：____
边界：做 ____；不做 ____
验收：____

## 节点
| # | 节点 | 产出 | 判定标准 | 依赖 | 状态 |
|---|---|---|---|---|---|
| 1 | 取素材 | 素材清单 | 覆盖全部附件 | — | 待办 |

## 风险与兜底
- 若 ____ 不可用 → 改用 ____

## 交付
- 产物：____（路径）
- 复核方式：____
- 遗留缺口：____
```
## 七、能力位接口 v1.2（2026-11-08）

- **查库前置**：接到专业问题时，先查分身路由表「专业知识位 v2.1」的 18 个新增包与既有 121 个 `taoge-*`，命中就按包内律判断；查不到再联网/找新技能。这一步不进任务树，但必须先做，否则容易重复造。
- **决策位**：`decide` —— 重大选择先挑承重问题，给结论＋"什么条件下改主意"。
- **项目位**：`pm` —— 多项目并行时用看板＋四象限排优先级，卡点进 `progress.md`。
- **破局位**：`unstuck` —— 被否/卡死先判"哪种不行"（资源不行/规则不行/假设不行），再给路径。
- **记忆位**：`second-brain` —— 旧结论先查库，不凭记忆复述；新结论回写 `findings.md`。
- **技能化位**：`skillify`＋`writing-skills` —— 同类活做到第三遍就固化成技能，写清触发条件与边界。
- **分工不变**：分身管"怎么想、怎么说"，统筹管"怎么排、怎么收"；能力位只补位，不新设角色。
