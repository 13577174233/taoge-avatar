# 开源量化项目方法论蒸馏（taoge-quant-method-distill）

> **一句话定位**：把四个研究类开源项目里经过工程验证的研判流程、信号契约与收口纪律，蒸馏成一套可直接回填到本地评估体系与日报的研究方法论；交易执行类项目的做法不纳入。
> **来源（2026-11-14 GitHub API 核实）**：TauricResearch/TradingAgents、openbq-org/OpenBB、ZhuLinsen/daily_stock_analysis、virattt/ai-hedge-fund；备选参照 microsoft/qlib、HKUDS/Vibe-Trading。
> **适用边界**：A 股/港股/美股个股与 ETF 的研究复盘；研究与执行分离，输出为证据支撑的观点与条件性参考，不构成投资建议，不代下单。

---

## 一、认知地图：一条研究流水线，六层职责

开源研究类项目的共性结构，可归纳为六层；本地体系回填时按层对齐，不引入重型框架。

| 层 | 职责 | 关键产出 | 蒸馏来源 |
|---|---|---|---|
| 取数层 | 多源行情、财务、股东机构、估值、研报预期、行业板块 | 标准化字段，失败留空不编造 | OpenBB、daily_stock_analysis |
| 特征/技术层 | 均线、MACD、RSI、KDJ、量比、支撑压力、阶段强弱 | 可复算的技术指标与证据行 | TradingAgents、ai-hedge-fund |
| 多视角研判层 | 基本面、资金、情绪、技术、行业地位分别给观点，多空对照 | 分维观点 + 多空证据清单 | TradingAgents、ai-hedge-fund |
| 信号收口层 | 各视角观点收敛为统一信号：置信度、动作档、周期、论点 | 结构化 Signal / DecisionSignal | ai-hedge-fund、daily_stock_analysis |
| 风险复核层 | 敞口、限额、立场冲突、证据充分性前置检查 | 复核意见与弃权/复核标记 | ai-hedge-fund、TradingAgents |
| 复盘闭环层 | 信号带期限与失效条件，后验命中/偏差，再评估 | 信号台账 + 复盘记录 | daily_stock_analysis、本地日报 v5.4 |

**纪律**：取数层不掺研判，研判层不直接给下单指令；风险复核在收口之后、对外输出之前。

## 二、角色分工链（多视角对照，不堆人数）

蒸馏自 TradingAgents 的分析师→研究员→经理→交易员→风控链路，以及 ai-hedge-fund 的大师视角、Vibe-Trading 的 Swarm 委员会。本地落地为一组固定视角，而非真的起多个 Agent。

| 视角角色 | 回答的问题 | 主要输入 | 对应本地维度 |
|---|---|---|---|
| 基本面研究员 | 营收/利润/ROE/现金流/负债质量是否支撑价值 | 财报、扣非、毛利率、净利率 | A 成长、B 盈利 |
| 资金面研究员 | 股东户数、机构/基金持仓、前十大变动是否集中或分散 | 股东户数比、机构家数、基金数、流通股东变动 | C 资金结构 |
| 行业研究员 | 所处行业景气、板块热度、行业内相对分位 | 板块涨跌、成分规模、市值/强弱/估值分位 | D 行业地位 |
| 技术面研究员 | 趋势排列、动量、量价、关键位与超买超卖 | 日 K、均线、MACD、RSI、量比、支撑压力 | E 走势技术 |
| 估值预期研究员 | 估值贵贱、机构盈利预测与目标价空间 | PE/PB/PEG、研报覆盖、EPS 预测、目标价 | F 估值预期 |
| 风控复核员 | 证据是否充分、观点是否冲突、是否需弃权/复核 | 各维得分与证据、数据质量摘要 | 收口前检查 |

**多空对照规则**：每一维得分 ≥65 列入多头证据，≤45 列入空头证据；落在中间区间不强行站队。多头清单与空头清单并列呈现，不先写结论再挑证据。

## 三、统一信号契约（所有视角收敛到同一结构）

蒸馏自 ai-hedge-fund 的 `Signal` 与 daily_stock_analysis 的 `DecisionSignal`。本地评估产出的每条观点/参考，建议带以下字段；取不到的字段记「—」，不留空泛表述。

### 3.1 观点字段

| 字段 | 含义 | 取值/口径 |
|---|---|---|
| model/source | 产生该观点的视角或来源 | 如 基本面/资金/技术/估值，或数据源标识 |
| ticker / date | 标的代码与观点形成日 | as-of 日期，只用该日及之前信息（point-in-time） |
| conviction | 观点置信度 | [-1, +1]：+1 偏多，0 中性，-1 偏空；0 表示无明确观点 |
| reasoning | 人可读理由 | 一句话论点，附关键证据行 |
| components | 量化分解 | 各子项得分与数值，便于回溯 |
| horizon_days | 观点兑现周期 | 短线(日内/数日)、波段(数周)、长期(季度以上)；评分按对应周期分级 |
| confidence | 证据把握度 | low / medium / high，与置信度分开：置信度是方向，把握度是证据充分性 |

### 3.2 计划与风险字段（持仓参考时）

| 字段 | 含义 |
|---|---|
| entry_low / entry_high | 参考区间下沿/上沿（条件性，非挂单价） |
| stop_loss | 复核/止损参考位 |
| target_price | 观察目标位（注明非一致目标价） |
| watch_conditions | 转入观察所需触发条件 |
| invalidation | 观点失效条件，至少覆盖价格、量能、时间三个可判定维度 |
| evidence / data_quality_summary | 证据摘要与数据质量摘要（哪些字段缺失、是否降级） |

### 3.3 弃权与复核语义

- **弃权（abstain）**：证据不足无法形成观点时，标记弃权，不硬给中性分；对应输出「证据不足/无法判断」并写明缺什么数据。
- **复核（REVIEW）**：模型或流程给出的结论无法识别出可读评级/动作时，标记待人工复核，**不得静默降级为 Hold/持有**；读不懂的结论不等于中性结论。

## 四、评分到动作的统一口径（含 guardrail）

蒸馏自 daily_stock_analysis 的 `decision-scale-v1`。综合分 0–100 映射到动作档；分数是证据汇总，动作是条件性参考，二者冲突时必须写解释。

| 综合分 | 信号档 | 动作口径 | 语义 |
|---|---|---|---|
| 80–100 | strong_buy | buy（偏积极） | 高胜率机会，可列入分批观察计划，仍受仓位纪律约束 |
| 60–79 | buy | buy（偏多） | 偏积极机会，允许有少量待确认项 |
| 40–59 | watch | watch / hold | 信号分歧或确认不足，等待触发条件 |
| 20–39 | reduce | reduce | 风险明显抬升，优先降低暴露 |
| 0–19 | sell | sell | 趋势或风险显著恶化，优先退出观察 |

**Guardrail（冲突必解释）**：若评分 ≥60 但最终动作是 hold/watch，或评分 <40 却仍是 hold/watch，必须给出明确解释（如「技术超买但基本面未变，转为持有观察」「估值低但趋势破位，暂不动作」）。不允许分数与动作脱节而无说明。

**动作枚举（8 态）**：buy / add / hold / reduce / sell / watch / avoid / alert。本地体系可保留现有中文标签（减仓止盈/止损复核/加仓观察/持有观察），但内部映射到上述枚举，便于台账与复盘统计。

**无仓与有仓分述**：同一只标的，无仓位与已有仓位的建议分开写。无仓给观察条件与参考区间；有仓结合成本价给浮盈浮亏、关键位与处置参考。

## 五、信号生命周期与后验复盘闭环

蒸馏自 daily_stock_analysis 的信号状态机，与本地日报 v5.4「预测-验证闭环」衔接。

| 状态 | 含义 |
|---|---|
| active | 信号有效，在期限内跟踪 |
| expired | 超过 horizon 期限自然到期，未触发失效条件 |
| invalidated | 触发失效条件（价格/量能/时间），观点作废 |
| closed | 已达成观察目标或已处置，闭环归档 |
| archived | 历史归档，仅用于复盘统计 |

**闭环动作**：
1. 每条对外参考落台账：代码、动作档、评分、周期、入场区间、失效条件、生成日、状态。
2. 下次评估首节先复盘上一批 active/expired 信号：命中、部分命中、未命中，标注偏差模式（位置判断错/时点错/证据不足/情绪扰动）。
3. 信号重估（reassess）需保留前后版本，不覆盖原记录。
4. 信号只记录建议、证据、风险、观察条件与来源；写入、提取、推送失败都不阻断主分析流程。

## 六、风险收口纪律

蒸馏自 ai-hedge-fund 的 risk/exposures、limits 与 TradingAgents 的风控经理环节。

1. **敞口与限额先于组合判断**：单票仓位上限、行业集中度先于加减仓建议检查；加仓观察必须带「分批 + 控制单票仓位上限」提示。
2. **多空不偏废**：输出看多论点时必须并列最有力的反解释，以及哪些后续变化会使判断不再成立。
3. **前视偏差门禁**：只用 as-of 时点之前可得信息；未收盘 K 线、当前成分股回看、未完成窗口、指标预热不足不得作为确认样本。
4. **数值稳健性**：打分前对 NaN/None/异常值做安全转换；百分位排名在可比样本内计算，样本为空给中性基准而非极端值。
5. **研究与执行分离**：可给条件性观察、参考位与失效条件；不给买卖时点、仓位数量、收益承诺或「立即执行」指令。

---

## 七、数据接入与降级纪律

蒸馏自 OpenBB 的可插拔分层与 daily_stock_analysis 的失败降级。

1. **数据源可插拔**：取数层按源封装，主源失败切兜底源；新增数据源不改研判与展示层。
2. **统一字段契约**：行情、财务、股东、估值、预期各走固定字段；源字段缺失时维度按可得权重归一化，取不到记「—」。
3. **降级留痕**：主源不可用、板块成分限流、ETF 无个股预测口径等，都在数据质量摘要里写明降级路径，不用代理指标冒充（如不以量比/换手率代理筹码集中度）。
4. **口径抬头**：每次研判先固定标的、市场、as-of、时区、频率、复权方式、指标参数与数据源预计算字段。

## 八、场景应用范式

### 8.1 单股研判（给定一只股票）
1. 定口径抬头与市场归属，取数并做数据质量摘要。
2. 五视角分别取证据、给分，形成多头/空头清单。
3. 收敛统一信号：置信度、动作档、周期、把握度、论点、失效条件。
4. 风控复核：证据是否充分、有无弃权/复核、分数与动作是否冲突。
5. 输出结构化研判：一句话结论 → 分维证据 → 多空对照 → 条件性参考 → 风险与失效条件。

### 8.2 组合批量评估（自选股整体）
1. 逐只走 8.1，生成个股信号与台账记录。
2. 组合层检查行业集中度、单票敞口与整体多空分布。
3. 汇总哪些标的信号转强/转弱、哪些进入失效或复核状态。

### 8.3 回填日报与评估体系
- 日报首节先复盘上一批信号命中情况，再出当日观点。
- 评估脚本在现有六维评分上补：动作档枚举、信号状态、观点周期、数据质量摘要、无仓/有仓分述。
- 不重复造已有能力：缠论/量价/支撑压力口径沿用日报 v5.4，本包只补结构化契约与收口纪律。

## 九、边界与不适用

- **不纳入**：加密货币交易机器人（freqtrade）、加密交易所统一 API（ccxt）、实盘交易柜台网关框架（vn.py）、重型编译型桌面终端（FinceptTerminal，AGPL 传染性）。
- **备选不装**：因子/ML 平台 Qlib、自然语言研究/回测工作区 Vibe-Trading；未来确有量化选股或回测需求再单独评估，本次不引入其依赖。
- **不做**：实盘下单、仓位资金安排、收益承诺、个性化投资建议；涉及个人决策时提示目标、期限与风险承受能力需自行匹配。
